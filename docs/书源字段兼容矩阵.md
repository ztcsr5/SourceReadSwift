读法：

- **栖阅**是四家里唯一把「仿真翻页 + 双栏 + 音量键翻页」都做了原生实现的（`PageCurlDriver`/`PageCurlWarmTask`/`ReaderPageControllerPool` 等，详见 `竞品翻页与阅读设置对照.md`）。
- **香色闺阁 / 源阅读 / 源阅**都靠 `UIPageViewController` 做仿真，香色闺阁额外用了 `CATransition`。
- **yidaApp** 只有滚动，没有翻页模型 —— 它是 Flutter 视频/阅读壳，不是书源阅读器。

## 四、结论（对纸间的实际意义）

1. **纸间的字段覆盖已经不低于「源阅读/源阅」这一档**：它们没有 `isVolume`/`formatJs`/`preUpdateJs`/`payAction`/`downloadUrls`，而纸间前四项都有实现。
2. **唯一明显更全的是栖阅**，它多出 `loginUi` / `loginCheckJs` / `jsLib` 预加载 / `downloadUrls` / `variableComment` 注释语义。这四项里，纸间真正该补的是 `jsLib` 的预加载语义（很多源把公共函数写在 jsLib 里，缺它等于规则跑不动），其余三项价值低或不适合做。
3. **`sourceRegex` 五家都有命中，纸间标「待验证」** —— 这是个明确缺口：它决定正文/目录的清洗正则是否进入元数据链，值得优先补 fixture。
4. **`downloadUrls` 不做是合理取舍**：只有栖阅碰它，纸间已明确「不做死按钮」。
5. **yidaApp 不在同一赛道**，可排除出对标集。

## 五、局限（必须写清楚）

- 字符串命中只能证明「认识这个名字」，不能证明解析语义；同一字段各家的 JSONPath 方言、函数集、过滤器行为都可能不同。
- 未做动态验证：没有 hook 也不会 hook（本机无越狱设备）。
- `wordCount` 在香色闺阁 / yidaApp 的命中可能来自 UI 文案而非书源字段，标为**噪声可能**。
- 纸间侧的「现状」列取自 `PROJECT_FULL.md` §5.6（项目自述），不是本轮实测。
