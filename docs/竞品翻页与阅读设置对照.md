## 一、栖阅（`com.arekert.qireader`，Swift + ObjC 混合）

正文层是 **WebView 竖向滚动**，分页层是原生 UIKit。可读到的 Reader 相关类共 53 个，关键这些：

| 类 | 作用（从名字与相邻符号推断） | 对应纸间 |
|---|---|---|
| `PageViewController` + `PageCurlDriver` + `PageCurlWarmTask` + `PageBackViewController` | 仿真翻页：`UIPageViewController` 驱动 + **预热任务**（提前把下一页/背面渲染好，避免翻到一半才加载） | 纸间 `PageCurlReaderView`，缺 warm 预渲染 |
| `HorizontalPagingViewController` + `PageContentViewController` + `ReaderPageControllerPool` | 平移翻页：横向分页 + **页面控制器池**（复用 VC，不每次翻页新建） | 纸间 `TabView` 分页，无池化 |
| `WebViewVerticalScrollViewController` | 滑动模式：整章丢给 WKWebView 滚（比 TextKit 省内存，但选择/高亮弱） | 纸间 `NativeReaderTextView`（TextKit 1） |
| `ReaderSpreadContentViewController` + `_doublePageMode` | 双栏跨页（iPad / 横屏） | 纸间无 |
| `ReaderLayoutCalculator` + `PageIndexCache` + `ChapterTitleHeightCache` + `ChapterTitleSnapshotService` | 分页尺寸、页索引、章标题高度都做缓存；标题用 HTML 渲染后截图缓存 | 纸间有章级分页缓存，标题无缓存 |
| `VolumeButtonPageTurnMonitor` + `_volumeButtonPageTurnEnabled` | 音量键翻页 | 纸间无 |
| `ReaderPresetFileManager` + `_layoutTemplate` / `_layoutWidgets` | 排版模板预设 | 纸间无 |

其他可直接用的开关字段：`_leftPageMargin` / `_rightPageMargin`（左右页边距分开设）、`_verticalScrollFullScreen`（滚动模式全屏）、`_readerBackgroundImageEnabled`（自定义背景图）、`_readerBottomToolbarStyle`（底栏样式）、`_readerUIFollowAppFont`（跟随系统字体）、`_chapterPreloadCount`（预取章数）、`_highlightRulesLayoutVersion`。

## 四、书源侧（只看 JSON，不做执行）

- 栖阅正文/目录走 `SwiftSoup`（包内可见 `_TtC9SwiftSoup12StreamReader`、`15CharacterReader`），说明它同样是 **Jsoup 方言**而不是 Jsoup 本体；纸间的 `HtmlRuleExtractor` 方向一致。
- 香色闺阁的 `plist_localConfig.plist` 里是本地书/导入配置，不含 JSONPath 规则引擎符号，其书源能力无法从二进制静态判断（需要行为观察），**这一条标为未验证**。
- 结论：JSON 书源的差异点仍在 `JSONRuleExtractor` 的方言边界（过滤器、函数、转换链），不是「别人有我们没有的引擎」。纸间已有的 60 例 JSONPath 测试是资产，应继续按差异补用例。
