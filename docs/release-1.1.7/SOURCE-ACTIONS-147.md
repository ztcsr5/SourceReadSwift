# Build 147 · 不再把更新提示算作正文

## 真机证据与更正

截图显示大灰狼的连续多章都把「您的书源版本过低，请及时更新书源！点击登录进行书源更新」渲染成正文。用户确认光遇有同类问题。前一份体检只断言提取到文字，因此《斗破苍穹》的 4/9 四级全绿不能当作四条可阅读；保留搜索、详情和目录的已知结果，正文结论以重新检查为准。不猜测作者要求升级的具体版本或验证方式。

## 改动

- 仅拦截全部内容为已知更新通知或其重复、章节标题、简单图片占位的响应。保留含真实正文的章节；旧缓存只移除此类确认的假正文，不重置书架或阅读进度。
- 真实解析和书源体检均把该响应标成「书源需要更新」，不通过正文检查、不保存为章节。失败页原地提供「打开书源更新」，继续使用原有书源表单。
- 大灰狼与光遇的「更新书源」脚本调用 Android `startBrowser` 打开内嵌发布页，旧实现丢弃了地址。现在仅在明确的按钮操作中展示发布页的 HTTPS 链接或拆出 `yuedu://booksource/importonline?src=…` 的 HTTPS 导入地址。不运行该 HTML，不发起网页脚本中的请求，不自动导入。复制后在原生书源管理确认导入。
- 合法的普通 HTTPS 浏览请求提供原生可点链接；Android 同步浏览器回传只显示明确的手动交接，不返回假结果、不标已登录，不伪造设备或账号状态。已有可用的原生网页和书源表单登录保留；两条源的实际作者授权是否成功未实测。
- 包含候选 Build 146 的魔丸目录规则及短响应/TLS 体检调整。Build 146 没有对假正文的拦截，不作为新交付。

## 验证

- macOS 同提交专项：真实输出近似 screenshot 的 HTML、正文引用通知不受影响、旧缓存清理而保留正常缓存、诊断拒绝假通过；原生发布链接捕获、不运行内嵌页面脚本、Android 登录等待不假造结果。
- 真机：大灰狼与光遇各从「斗破苍穹」重新进入章节。若发布方仍返回提示，要看到错误页和「打开书源更新」，不能再看到该提示占一章。点「检查书源更新」时核对作者域名，再在书源管理导入；返回后重试，必须看到真实正文才算恢复。
- 不改原生侧滑、主题、正文排版、书架数据格式；源规则没有被替换或重新发布。按本批提交回滚。
