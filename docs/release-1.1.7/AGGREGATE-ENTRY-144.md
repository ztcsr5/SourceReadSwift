# Build 144 · 聚合书源入口

## 用户实测与范围

Build 143 真机反馈：五类聚合来源都搜不到书，分类寻书点进去也失败。Build 143 的搜索、目录与正文合成样本不能证明这些来源已连通。本轮只动列表入口：搜索 URL、分类 URL、脚本请求与错误归类，不改寻书旧版 UI、书架、目录或阅读器。

## 从样本核实的规则形态

用户 JSON 只做离线结构读取和语法分析，未执行原脚本、未访问其站点、未将附件入库。

| 来源 | 搜索入口 | 分类入口 |
| --- | --- | --- |
| 大灰狼聚合 | JS 拼接 URL 与请求选项 | 菜单含普通分页链接和独立浏览器操作 |
| 光遇聚合 | JS 生成 `data:;base64,`，后续 JS 脚本处理再走 JSONPath | 菜单含普通分页链接和独立浏览器操作 |
| 书山聚合 | JS 生成入口，列表走 JSONPath | 分类有计算页码，列表脚本还读取当前页 |
| 听雪聚合 | JS 生成请求，列表是 JS 接 JSONPath | JS 生成链接菜单和分页规则 |
| syiism 聚合 | `@js:` 调用库函数 | 分类 URL 有页号，可能有脚本子请求 |

听雪和书山还声明了脚本形式的源请求头。当前解析器不执行这种请求头；原先会错误地把脚本文本当作字面 HTTP 字段，本轮只阻止错误发送，不声称它们所需的动态头、账号或 Android 环境已兼容。浏览器配置入口不能当作分类请求；不会代替用户登录、生成或绕过凭据。

## 改动

- 分类列表复用搜索已有的 Legado 入口解析器，先得到实际地址，再使用页码、请求方法、正文和选项；本地 `data:` 地址不执行二次替换。
- 普通搜索 URL 和分类 URL 都把当前请求的页码以及可用的关键词传给列表脚本；非 URL JS 返回值不再变成对首页的误请求。
- JS 子请求失败保留为阶段错误；保留 HTTP 状态码，不输出请求头、完整 URL 或响应正文。取消对发生在搜索 URL 脚本执行期间的异常进行隐式重跑；只兼容确实属于顶层 `return` 的语法情况。
- 直接返回 JS 错误与“上游正常、规则没有命中任何书”分别报告。

## 验收与回滚

- Windows 检查：Python 工程测试、Swift parser 增量检查、名称检查、`git diff --check`；这不等于 Xcode 编译。
- macOS `source-rows-probe.yml`：离线验证分类两段脚本、当前页、请求选项、内嵌搜索手递手、出错不误发、不重发；另跑现有搜索 URL、请求体 JS 和旧语料回归。IPA 看同一 HEAD 的 `unsigned-ipa.yml`。
- 真机：同一关键词分别对上述五条源单源全网搜索；每条源分别记录菜单是否出现、普通分类页是否出书。不要把登录/浏览器入口当成书单。若仍失败，只回报来源名、阶段和首条错误或 HTTP 状态码，不发送 Cookie、Token 或原始请求头。未跑真实站点，不能承诺聚合源全部可用。
- 不涉及数据迁移；独立功能提交可用 `git revert <commit>` 撤销。设备回退不需要清空现有书源或书架。
