# Build 140 · 寻书、主题与导航修订

## 从 Build 139 重新定方向

Build 139 的寻书把六个常驻入口、互相竞争的彩色标签和结果框放在同一层，造成「操作比内容响」。四套氛围主题大多靠更换配色、小图和装饰边框，画面不够完整。封面归位还引入了已明确禁止的 Zoom。本轮不沿用这三个设计决定。

- **参考 Apple Books 的阅读层次**：封面、标题、作者是结果的阅读顺序，外壳不反复强调「卡片」。[Apple Books 的寻书入口](https://support.apple.com/en-asia/guide/iphone/iphc1af7c57/ios)。
- **参考 Libby 分开查询、分类和细筛的方式**：搜索不用先选择任何筛选，筛选仍可达，分类恢复它自己的书源与目录。[Libby 搜索](https://help.libbyapp.com/en-us/6001.htm) · [Libby 分类浏览](https://help.libbyapp.com/en-us/6132.htm)。
- **把主题当独立装帧**：日夜共享版面和内容，不复用同一张图强压黑。画册先看真实画幅，查看不写偏好，显式应用才改变 App。页面上正文/操作区保持净纸，插画只从底部进入；不在结果行加入实时模糊或独立动画。

## 界面与资源

| 区域 | 实现 | 验收标准 |
|---|---|---|
| 寻书首屏 | 两个文字页签，一条搜索框；最近搜索和示例查询按行排列，不冒充实时热门 | 首屏无结果标题、无常驻匹配控件；搜索框和筛选 44 pt 以上 |
| 分类 | 书源、内容类型、分类各占一行；分类与来源在独立选择器里，不被横滚裁切 | 无分类时仍能调内容类型；保留源自带控件及翻页 |
| 搜索结果 | 封面、两行书名、作者/来源、简短摘要；弱分隔线，列表/网格收入工具菜单 | 仍能打开详情、查看其他书源、加入书架；空态、失败、取消可见 |
| 主题 | 用同一画幅作日夜印样，画册独立入口，单个「应用主题」动作 | 四套各两图、实时可切，预览不能改变森林绿或系统明暗 |
| 主题应用 | 同步实际 App 纸色、强调色和大幅插画；合成前解码并复用缓存 | 不影响森林绿纯白、原生阅读玻璃、正文纸张设置；不更改旧主题 rawValue |

插画为本轮新增原画，各 960 × 1440，日夜以同一构图配对。水墨丹青是暖宣纸、松烟和朱砂；竹雨江湖是青竹、湿石和旧金；晴空小镇是粉蓝光线和靛蓝暮色；花信手账是杏色纸与干花。原四套核心主题和相册自定义工坊保持。四套新强调色对各自卡片底色的静态对比度为 5.88:1–8.28:1；最终屏幕尤其底端的对比度仍要查实图。

## 桌面图标

本地抽查了用户测试的 Build 139：iPhone／iPad 的最终 Info.plist 都声明了七个备用名称；两份独立 PNG 仅属于主图标。由此不能推断报错 -54 一定由签名或素材造成。Build 140 为备选补齐设备尺寸输入，仍使用 Xcode 生成图标声明，CI 同时读取 IPA 的 Info.plist 和 Assets.car。前台请求后以 `alternateIconName` 为准；系统拒绝时，不会先改 App 内图标或把相册徽标当作桌面图标。[Apple 备选图标配置](https://developer.apple.com/documentation/xcode/configuring-your-app-to-use-alternate-app-icons) · [UIKit 返回契约](https://developer.apple.com/documentation/uikit/uiapplication/setalternateiconname(_:completionhandler:))。

真机验收：同一 iPhone 上用一致的 Bundle ID 覆盖安装，选一个内置备选，再恢复默认；两次都检查桌面实体图标和 App 内显示。若仍报 -54，记录 iOS 版本、签名／安装工具及同一次请求的 domain/code，再与用 Xcode 开发签名直接安装对照。没有签名证据前不要求卸载或清空数据。

## 导航边界

没有任何导航 Zoom 或隐藏开关；保留系统边缘返回和平移默认。旧「封面归位」回退系统；旧「书页收合」沿用纸页视差，前景移动时没有缩放。不改漫画双指放大，不改正文翻页／选字的手势优先级。用真实拖拽验证取消、完成、首次再开和原会话续读。模拟器录屏不替代 ProMotion 真机测量。
