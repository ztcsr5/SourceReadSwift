## 修复及验证入口

- **聚合登录接线**：大灰狼、光遇的作者按钮都明确调用 `login(true)`。通用「登录」以前只识别少数无装饰标题及 `login()`，两条都没匹配。现在匹配已知登录标题、保留原动作与实参；不把「检测登录」「退出登录」当成登录。作者没有校验规则时不能自动关闭面板当成成功。使用两个实际标签的离线用例，并验证合成登录状态与规则版本原样带到正文 POST。
- **批量测试状态保留**：读超过 100 条源会淘汰最早的规则状态；有登录字段/会话请求头的源之前也一并淘汰。现在仍维持 100 条内存上限，先淘汰普通规则缓存；不额外保存用户密码，不修改 Keychain 策略。用 449 次合成状态切换验证登录状态仍在且不会串到另一源。
- **通用请求链**：详情、目录、正文、配置表单共用已有搜索侧的单次 JS 传输。真实请求没有响应时返回明确的无响应状态，不再走第二个本地回退分支再发 POST；真实 HTTP 错误仍交还给作者脚本处理。用合成正文 POST 无响应样本核对实际发送一次。
- **书山等接口拒绝**：HTTP 200 且仅有明确拒绝错误的 JSON 不再误报为空列表。不放宽证书／重定向校验，不伪造设备、作者版本、Cookie 或通过率。

## 复测与验收

1. Windows 使用 `python -B -X utf8 -m unittest discover -s scripts -p "test_*.py" -q`；语法、名称及 Git diff 审计是静态检查，不替代 iOS。
2. macOS 的同一提交跑 `source-rows-probe.yml`、`unsigned-ipa.yml`；验证生成的是正确构建号的 arm64 IPA。离线样本只证明客户端改动的行为。
3. 候选 IPA 在 iPhone 上先单测大灰狼、光遇两条，检查点作者登录后、进入真实正文、退出正文再打开；随后在同一次 App 运行里跑 440 源，再回到这两条源验证会话。Android 专属回调、外部源站故障与真实账户授权未在离线测试覆盖。
