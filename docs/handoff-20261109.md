## 六、关键技术结论（有证据，别再重新论证）

### 渲染架构对比

| App | 正文渲染 | 帧率表现 |
|---|---|---|
| **益达 1.4.4**（用户最认可） | Flutter 自绘 + **Impeller(Metal)**；正文 `TextPainter`，无 DOM；Rust 核心（FRB，AWS-LC/TLS/RequestClient）负责网络与解析；`shaders/stretch_effect.frag` 自绘过滚 | 视频量化：808 运动帧 **0 次冻结** |
| **栖阅 2027.01.01** | **WKWebView** + 章节窗口化 + 上下 spacer + `elementFromPoint` 探针锚点 + 260ms 进度节流 | 未实测（用户无法使用） |
| **纸间（当前）** | WKWebView + JS 桥，setContent 全窗口补丁 | 视频量化：1063 运动帧 **13 次冻结**（占 1.2%） |

### 已验证结论

1. **视频录屏不能测 Hz**（录制本身 22–30fps）。要看真实帧率只能用 `CADisplayLink` 采样。
2. **常驻 120Hz 的实现方式**：`CADisplayLink` + `preferredFrameRateRange(120,120,120)` + `Info.plist CADisableMinimumFrameDurationOnPhone=true`（已有）。Flutter 的 iOS embedder 就是这么做的，不是私有能力。
3. **两个曾导致「只有 60Hz」的坑**：`UIScreen.main.maximumFramesPerSecond` 可能返回 60；采样器当初故意不请求 120 → 读数永远 60。均已修。
4. **「返回主页第一下不能动」的根因**：转场结束后 SwiftUI 仍在重算 `BookshelfView.body`（1497 行 + 派生集合每次 filter + `onAppear` 写 `@State` 触发第二轮），主线程被占，触摸排队未处理。修法：派生集合缓存 → pin 幂等 → 拆子树。
5. **搜索收起栏系统不会自动做**，必须自己隐藏 tabBar 并提供返回控件（已实现）。
6. **卡片硬切的原因**：书架走的是 sheet，sheet 没有 zoom 转场；改成 push + `bookHeroDestination` 即可。
