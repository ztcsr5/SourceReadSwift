## 7. 因果链与接手优先级

**高置信 Inferred 工程因果：**

1. 反馈场景重复 → 多轮分别改几何、段距、宿主、预热和兜底 → 没有统一“正文守恒/位置守恒/交互状态”回归 → CI绿之后同类反馈仍出现。
2. 末行裁切 → 8pt再16pt固定buffer → 可改变可容纳行数，却不能修复弱缓存key与测量/渲染不一致；本轮分页审查已发现这两类代码事实。
3. 快翻拖拽 → 扩槽位/页预热/章半径/全窗口同步 → 某些冷帧可能改善，但主线程同步量亦增大；没有设备profile就不能用“更大缓存”证明“更快”。
4. 页码/章号/宿主可见内容各有状态 → 仅修一个settling布尔或回调超时 → 不能覆盖预取插章、模式切换、旋转、反向拖动的组合时序。

**建议下一轮不是再升119补常量，而是建立可失败的验收夹具：**

- 锁同一本地书、同一末章、同一字号与设备/系统原始信息；记录包版本、内容哈希、模式、容器几何。
- 先检正文分片拼回是否与原文一致、缓存冷/热结果一致；把渲染revision与定位identity分开。
- 交互回放：轻触零位移、拖后取消、快速同向/反向、连续跨5章、目录跳后跨章、模式切换、字号/旋转；每次核对可见页identity与页码。
- 用最终富文本与实际UITextView验证可见字形范围，不继续仅用最后一句contains或几何常量断言。
- 主线程分页/富文本/宿主更新与首帧耗时分别记录；以设备测量裁决预热预算，避免同步11章与后台重复分页。
- 以上未通过前，文档状态保持“代码已改/未验收”而非“根治”。具体代码发现见`pagination-audit.md`与`project-audit.md`，控制器审查以对应最新文件为准。
