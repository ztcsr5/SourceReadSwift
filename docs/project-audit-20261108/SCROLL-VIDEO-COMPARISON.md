## 可直接观察的内容

- 蓝色约 1.1–5.3 s 在第 156 章内连续竖向滑动；这段没有展示跨章边界。随后打开设置并切换到横向分页，不能把后半段当作连续滑动样本。
- 白色约 1.0–9.4 s 从第 3/4 章附近跨到第 7 章；约 3.4 s 已显示第 5 章，约 6.8 s 显示第 6 章。它比蓝色包含更多章节加载/边界变更场景。
- 白色 8.600 s 的下一张编码视频帧在 9.333 s，相隔约 0.733 s；9.333 s 画面中第 7 章标题已进入下半屏。10.100–10.800 s 另有 0.700 s 间隔，后者正文几乎静止，不能当作同一种滚动停顿。
- 白色后半程出现“页 2/7”等分页状态，验证连续滑动时需截取前半段。
- 录屏时间戳并非完全均匀；文件的平均帧率仅描述录制结果，不是设备渲染 FPS。

## 结论与限制

重点复测白色连续跨章时的突停、章间留白和标题进入顶部的过程。现有修复对应已能复现的代码机制：滚动中章节补丁/裁窗打断惯性，以及章间负锚点被钳零造成约 22 px 跳动。没有用修改减速常数来掩盖这两类问题。

单靠此录屏无法证明 0.733 s 是源请求、缓存读写、主线程布局或录屏编码造成；也没有手指按下/抬起轨迹，不能把一次松手后的减速误判为卡顿。两段文本、字体和章节长度不同，不能按滚过章节数评定优劣。录屏未包含版本标识，不能据此宣称最新 `565a44e` 已复现相同卡顿。

## 同场景复测

使用桌面的 `SourceReadSwift-1.1.8-build138-565a44e-unsigned.ipa`（未签名）。在相同书籍第 3–7 章分别冷缓存、热缓存连续向上拖动并松手，让惯性跨过标题；同时快速连续滑动和反向滑回上一章。预期已显示正文不闪回、不跳约一行，加载完成不终止惯性；退出重开保持阅读位置。慢源确实未返回正文时仍可能等待网络，不以隐藏提示冒充加载完成。

双系统专项测试和 Release 构建已通过，详见 [SCROLL-HITCH.md](SCROLL-HITCH.md)。真机同场景帧时间尚未采集，保留这个验证边界。

## 重现分析

```powershell
python -B -X utf8 scripts/inspect_scroll_videos.py F:/SourceReadSwift/reader-quality-137/user-scroll-videos '<YIDA_VIDEO>' '<SOURCEREAD_VIDEO>'
```

将两个占位符替换为本机原视频路径。预期输出两个原件 SHA-256、尺寸、帧数与派生证据路径。`motion.csv` 的光流仅在有效跟踪点充足时参考；快速移动、模式切换和弹层会使估计失效，不把空值填成零速度。
