# 轻阅书源诊断数据分析（关键词「剑来」，991 源）

> 数据：`轻阅书源诊断数据_1792882175.json`（3,739,243 字节，991 份 report，关键字「剑来」）
> 分析方式：按 `stage × status` 聚合、按 `failureCode` 分类、对 `failureClassification` / `responseSummary` 归一化后计数。

## 一、总览

| 阶段 | passed | warning | failed | blocked |
|---|---:|---:|---:|---:|
| search | 687 | **196** | **95** | **13** |
| detail | 656 | 7 | **24** | 0 |
| toc | 551 | **102** | 2 | 1 |
| content | 544 | 3 | 3 | 1 |

搜索阶段 `passed` 只占 69.3%，warning + failed + blocked 合计 30.7%。**warning 比 failed 更值得看**，因为它意味着「请求通了但没解析出东西」。

## 二、真正的失败原因（failed / blocked）

| 阶段 | 失败码 | 次数 | 代表文案 |
|---|---|---:|---|
| search | `network` | 51 | **`URL 格式非法或解析异常 (-1000)` ×31**、`HTTP 404` ×23、`连接丢失` ×20、`域名未解析` ×9、`HTTP 412` ×3 |
| search | `blocked` | 13 | `HTTP 403 源站拒绝访问` ×7、`Cloudflare 5 秒盾` ×3、`地区拦截/WAF` ×3 |
| search | `parsing` | 41 | 见下（解析为空被归到 warning，这 41 是解析抛错） |
| search | `javascript` | 3 | 源内 JS 抛错 |
| detail | `network` | 24 | `HTTP 404` ×14、`HTTP 405` ×3、`502` ×2 |
| content | `network` | 3 | — |

**最扎眼的一条：`URL 格式非法或解析异常 (-1000)` 31 次**。这不是站点问题，是拼 URL 的问题——`searchUrl` 模板在某类写法下拼出了非法 URL（多半是关键字没转义、或相对路径没跟 `bookSourceUrl` 拼接）。这一条是**我们能改的**。

## 三、warning 才是最大一块（请求成功但没结果）

| 阶段 | 文案 | 次数 |
|---|---|---:|
| search | 搜索解析结果为空 | **140** |
| search | JSON 搜索解析结果为空 | 28 |
| search | 搜索超时（>12s） | 11 |
| search | 源站响应内容为空（仅 N 字节） | 3 |
| toc | Chapter list is empty | **52** |
| toc | JSON chapter list is empty | **40** |
| toc | 目录超时 | 5 |
| toc | API 返回「鉴权参数无效」 | 3 |
| detail | 详情超时 | 3 |

合计 **168 条搜索空解析 + 92 条目录空解析**。它们分三类：

1. **响应类型与规则不匹配**：HTML 规则打 JSON 响应（或反过来）。JSON 侧空 28 条、目录 JSON 空 40 条，说明确实有一批源被当成另一种格式在解析。
2. **规则选择器本身失效**：站点改版，`div.bookbox` 这类选择器不再命中。
3. **超时被当成空**：11 + 5 条超时，当前 12 秒阈值对慢源偏紧。

## 四、可以直接落地的引擎侧改进（按收益排序）

| 优先级 | 改进 | 依据 |
|---|---|---|
| P0 | `searchUrl` / `tocUrl` 的 URL 归一化：关键字强制百分号编码、相对路径按 `bookSourceUrl` 解析、非法 URL 在请求前给出可读诊断（而不是 -1000） | 31 条 -1000 |
| P0 | 响应类型自动纠错：规则是 JSON 而响应是 HTML（或反之）时，自动换用另一套提取器重试一次 | 28 + 40 条空解析 |
| P1 | 空解析诊断细化：选中阶段（0 命中）时把「选择器未命中 / 命中但字段空 / 响应为空」分开报 | 140 条只报「结果为空」 |
| P1 | 搜索/目录超时 12s → 20s，并对超时源做一次重试（保留 `retryable`） | 11 + 5 条超时 |
| P2 | 目录空解析时回落到 `nextTocUrl` 二次抓取再判定 | 52 条 HTML 目录空 |
| P2 | 403/Cloudflare/412 这类 blocked 明确标注「需要 WebView 登录或人工验证」，不再计入「解析失败」 | 13 条 blocked 与解析失败混在 failed 里 |

## 五、不建议做的事

- 不要按单个源的域名写特判（991 个源、域名分散，特判不可维护）。
- 不要把 404/403 归成「解析问题」——那会让健康度指标失真。
- 不要为了少报错而放宽「空结果」判定：空结果就是空结果，改的是诊断粒度。
