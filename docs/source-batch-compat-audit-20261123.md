## 实现与检查

- 并排书架是独立选项，森林绿上半区复用静态柔雾，下方回到亮色纸白，暗色保持暗色；不改默认展台、高刷新率与其他布局。主书点击直读，两侧切换预览，完整书架有单独入口。
- 大封面按裁切短边和屏幕倍率计算所需原图像素，最多解码到 1,024 px 长边。800 × 1,600 合成样本在 480 px 宽的目标上，旧最长边缩略得到 345 px 宽，新预算保留 512 px 宽；没有更改小封面缓存预算或放大低清原图。这是离线像素对照，不是真机画面。
- 手选类型优先于旧书籍缓存和规则推断，保存到书源库组织偏好；可恢复自动，重导入和备份不会丢掉本地偏好。分类诊断可从发现进入；流媒体优先正确的播放字段和标签。
- Windows 本地 Python 检查：318 项，317 通过、1 跳过；68 个 Swift 文件无新增语法诊断，`git diff --check` 通过。未运行 iOS XCTest、Xcode 编译、LiveContainer 真机或外部端到端语料。

## 接续验收

1. 在有 Xcode 的环境用同一候选代码构建项目，生成本地且不入库的语料目录。按附件顺序传入 `scripts/inspect_source_inventory.py --output <收据.json> --stage-native-inputs <私有新目录> <8 个原始文件>`；产物只允许在受控目录使用。
2. 先用现有 `PrivateSourceCorpusProbeTests/testExternalPrivateCorpus` 的 inspect 模式看结构。获准执行后用 live 模式和原文件索引分段验证，配套 `TEST_RUNNER_PRIVATE_SOURCE_CORPUS_VERIFY_PLAYBACK=1` 与当前完整 `TEST_RUNNER_PRIVATE_SOURCE_CORPUS_REVISION`。这条工具默认不启用 WebView 回退；必须借助 WebKit、真实登录或特殊设备的定义另做实机验证，不把它们视为失败的根因或成功样本。
3. 聚合时使用 `--native-report <候选私有收据…> --revision <候选完整 SHA>`，同时传同一组原始附件。脚本拒绝旧版本或丢失原行的收据，提取到流地址不算通过。
4. 主线测试 IPA 只提供功能试用。等到下一版有同一候选 SHA 的逐源证据，再判断是否达到 90%，不沿用旧包或本轮 IPA 打包的状态。
